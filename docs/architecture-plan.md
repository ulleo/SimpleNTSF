# SimpleNTFS 架构修改计划

基于 2026-10-18 对 `71c4d6f`（v1.2.1）的审查。建议先修复可见的状态错误，再逐步集中状态管理、命令执行、磁盘查询与挂载能力规则。每阶段单独验证和提交，使结构调整不掩盖行为变化。

截至 2026-10-19，五阶段代码实现和自动化回归已完成，保留既有 sudoers 机制，并落实批量部分失败、卷状态未确认的处理规则。下文保留最初的阶段计划及设计依据；当前交付证据和未验证范围见文末。最终独立代码审查及其两项改进已完成，GitHub 任务尚未关闭。

## 目标与兼容约束

- 刷新完成意味着可见状态已经更新；旧查询不能覆盖较新的配置或操作结果。
- 新增、修改、删除挂载配置后，持久化内容与内存中的目标挂载点一致。
- 所有磁盘查询都有明确的结束条件；查询失败与未挂载分开表达。
- 单盘、重新挂载和批量操作都保留结果，失败后仍能显示可信的卷状态。
- 批量操作中单卷失败不终止其余卷的处理，结束后汇总失败的卷及原因；重新挂载部分失败不自动反复重试。
- 卷状态查询失败或超时后，保留已有信息并标明“状态未确认”，暂时禁用该卷的挂载、卸载和重新挂载；允许刷新重试。
- 保留当前 macOS 12.0、arm64 目标及 `build.sh` 应用打包入口。
- 保留 `~/.SimpleNTFS/ntfs-disks.conf` 的 `UUID:挂载点路径` 格式，避免迁移用户配置。
- 保留现有 sudoers 机制；修正判定与规则一致性，权限机制替换不属于本轮范围。

领域词汇见 [GLOSSARY.md](../GLOSSARY.md)。新增 module 的名称仅表达职责，具体文件划分与 interface 在进入对应阶段时确定。

## 阶段 1 修复直接错误并建立行为验证

先增加不依赖真实磁盘和管理员权限的独立测试入口。审查时仓库没有 Package.swift、Xcode 工程或自动化测试；建议以单独的 `test.sh` 编译并运行行为测试程序，产物写入临时目录，避免为引入测试先迁移整个构建系统。需要控制查询完成顺序和配置读写位置，因此只引入这些测试实际需要的 seam；暂不搭建通用依赖注入框架。

1. 调整刷新完成时机：在状态发布后结束加载，手动刷新也接入同一加载状态。刷新期间再次请求刷新，不得立即以“已完成”回应；合并或排队策略在阶段 2 固化。
2. 成功读取空配置时发布空列表；读取失败与成功读到空内容分别处理，不能因读取失败而把旧列表当作已清空。
3. 编辑目标挂载点后，内存使用与文件相同的规范化路径；只修改目标字段，保留文件系统类型、超时信息和实际挂载点。
4. 修复权限路径子串误判：旧配置中的 `mount_ntfs` 不能充当独立的 `/sbin/mount` 授权项。测试从权限判定的行为入口进入。

证据：`DiskManager.swift:99–175`、`214–233`、`479–493`；`ContentView.swift:293–295`、`390–395`、`399–407`。

**验收**：删除最后一项后列表为空；查询未结束时仍保持加载；输入 `~/Mounted/example` 后当前显示与重载结果一致；编辑后类型标签不消失；旧 NTFS 权限配置不再被误判为已覆盖系统 mount。

## 阶段 2 集中配置与卷状态

深化配置与卷状态 module，让它拥有持久化变更、状态发布和操作完成的规则。ContentView 保留确认交互和展示，不再承担“先写文件、再改内存、再刷列表”的顺序约定。

- 将对可见状态的修改集中在同一个执行上下文；后台工作返回结果，统一决定是否接受。
- 推荐合并重复刷新请求，并在查询期间发生配置变更时安排后续刷新；无论最终采用排队还是版本标记，都必须拒绝过期结果。
- 统一目标路径的展开、规范化和校验，避免新增视图、编辑视图与保存逻辑各自维护规则。校验目录归属时不只比较字符前缀；符号链接场景纳入验证。
- 配置读写失败必须传回调用方；写入成功后再发布相应配置状态。添加配置不能把读取失败当成空文件继续覆盖。
- 重新挂载无论成功或部分失败，都重新核实卷的实际状态；第二步失败时不自动反复重试。查询失败时显示“状态未确认”，不能继续断言旧状态有效。
- 卷状态查询失败或超时后保留上次信息作为参考，禁用该卷的挂载、卸载和重新挂载；首次查询就失败时不伪造历史信息。刷新入口保持可用，查询成功后按核实到的状态恢复相应操作。
- 批量操作开始时取得稳定的目标集合，串行处理可操作的卷；单卷失败后继续其余卷，记录逐卷结果。状态未确认的卷不执行磁盘操作，并在汇总中说明跳过原因，避免批量入口绕过单盘限制。
- 批量结束后统一列出失败的卷及原因，并完成状态刷新再解除忙碌状态。

**depth** 来自 module 吸收完整时序，而非增加转发函数；**locality** 来自状态规则集中，**leverage** 来自单盘、批量和配置操作共用这些规则。

**测试 seam**：可控查询 adapter 与临时配置文件 adapter。测试和视图通过同一行为 interface 观察结果，不直接操纵内部状态。

**验收**：慢旧查询不能恢复已删除的配置或覆盖新目标路径；重复请求均得到正确的完成结果；写入失败不显示保存成功；重新挂载第二步失败后展示核实结果且不自动反复重试；批量部分失败仍处理后续卷并指出具体失败；状态未确认的卷不能经单盘或批量入口执行磁盘操作，刷新成功后恢复适用操作。

## 阶段 3 集中命令生命周期

创建有实际职责的命令执行 module，吸收启动、输出读取、退出、超时与资源清理。磁盘格式解析和挂载决策不放入它的 implementation。

- 运行期间读取 stdout 和 stderr，避免先等待退出、再读取输出导致管道阻塞。
- 区分启动失败、非零退出、超时与正常结束，保留必要的错误信息。
- 统一等待时限和终止后的清理；不能把“已发出终止信号”直接解释为“操作未发生”。挂载超时后的真实状态由阶段 2 的操作流程核实。
- 普通查询、挂载和管理员交互使用各自的等待策略，不能把短查询时限机械套到密码提示上。
- 替换现有执行点时逐处接入，删除被替代的重复实现。特别补齐新增扫描当前没有时限的路径。

**测试 seam**：真实 Process adapter 配合可控的无副作用测试子进程，验证实际管道行为；上层查询可使用固定结果 adapter。

**验收**：大输出不会卡住；进程启动失败可报告；超过时限能结束等待并处理资源；扫描遇到一个无响应卷不会无限加载；既有挂载命令参数不因迁移被无意改写。

## 阶段 4 统一磁盘发现与查询

深化磁盘信息 module，让新增扫描与配置列表刷新共享完整的卷信息和错误语义。删除 AddDiskSheet 中直接执行系统命令、理解磁盘输出格式的逻辑。

- 一次卷详情查询提取设备名、卷名、文件系统类型等字段，避免分别执行三次相同查询。
- 先核实目标 macOS 上可用的结构化命令输出及字段，再选择解析方式；不在计划阶段假定格式完整覆盖所有卷类型。
- 让发现规则与已支持的文件系统一致，验证 NTFS、exFAT、FAT32、APFS、HFS+；区分物理硬盘与其承载的卷。
- 完整保留含空格或冒号的卷名及路径；容量查询使用实际挂载点。
- 区分卷离线、未挂载、缺失标识、查询超时和解析失败。不要再依靠“未找到”等展示字符串驱动业务判断。

**seam / adapter**：系统查询 adapter 与固定输出、可控失败的测试 adapter 支撑同一磁盘信息 interface；不为每个字段另造 shallow module。

**验收**：新增和刷新对同一卷给出一致信息；带空格路径完整保留；新增文件系统支持有配套发现样例；缺失字段与拔盘有明确结果；有限并发不会造成大量进程同时启动。

## 阶段 5 对齐挂载能力并完成回归

在已确认保留现有权限机制的范围内，让文件系统对应命令、所需权限和配置状态判定使用一致的规则。只有 NTFS 与系统挂载的真实差异需要 adapter；不预先建立可扩展插件体系。

- 集中支持类型与挂载命令的对应关系，对未知类型给出明确结果，避免悄悄落入默认命令。
- 权限判定考虑对应用户和完整命令项；不能把任意路径子串或配置文件存在等同于权限有效。
- 区分“配置内容满足预期”和“执行时实际获授权”，让运行时权限失败能够纠正界面提示。
- 修正规则生成、判定与挂载选择之间的重复知识，同时保持阶段 1 的旧配置回归测试。
- 更新 README 中的支持格式、限制、构建和测试方法；新增源码同步纳入 `build.sh`。

**验收**：旧配置、缺命令、错误用户及完整配置都有可区分结果；NTFS 与系统挂载使用对应规则；原有配置文件无需迁移即可加载；所有阶段的行为测试与应用编译通过。

## 已确认的设计选择

1. 先修稳定性，再分阶段调整结构；阶段 1 可独立交付。
2. 保留 sudoers 机制，修正权限识别与规则一致性，不替换权限机制。
3. 批量操作部分失败时继续处理其余卷，最后统一汇总；重新挂载部分失败后核实状态，不自动反复重试。
4. 查询失败或超时后保留上次信息但标记为状态未确认，暂时禁止依赖该状态的磁盘操作，允许刷新重试。

刷新期间维持现有交互约束；未知或不支持的文件系统明确提示不能挂载。代码与环境事实由检查确定，不要求用户自行调查。

方法名、文件数量和并发实现手段在计划阶段未固定，已在各任务实施时确定。当前没有需要记录为已接受 ADR 的不可逆架构决策；真实权衡确定后再按需记录。
